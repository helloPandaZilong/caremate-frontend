CareMate 모니터링·알림 연동 테스트 프로토타입

프론트 dev 서버에서 이 파일을 열면 실제 백엔드 API와 SSE를 브라우저 기준으로 점검합니다. 로그인 → SSE 구독 → 알림 목록/읽음 → 고객 타임라인 → 수리점 상태 전이 → 결제/청구 흐름까지 한 화면에서 확인할 수 있습니다.

사용 방법: 이 파일을 caremate-frontend/public/caremate-monitoring-alarm-integration-prototype.html에 넣고 npm run dev 실행 후 http://localhost:3000/caremate-monitoring-alarm-integration-prototype.html 로 접속하세요. Vite 프록시를 타면 API Base는 기본값 /api 그대로 쓰면 됩니다. 상태 전이/결제/청구 버튼은 실제 DB를 변경합니다.

2. SSE 실시간 알림

EventSource는 Authorization 헤더를 못 붙이므로, 백엔드 규약처럼 ?token=accessToken으로 연결합니다.

3. 알림 API 테스트

알림 목록, 미읽음 개수, 읽음 처리를 확인합니다. 알림 클릭 이동 경로도 같이 표시합니다.

4. 고객 모니터링 타임라인

선택한 고객 토큰으로 GET /customer/repair-orders/{orderId}/status-histories를 호출합니다.

5. 수리점 주문 워크플로우

아래 버튼은 실제 주문 상태를 변경합니다. 먼저 주문 목록에서 테스트할 주문 ID를 선택하세요.

6. 결제·청구 흐름

REPAIR_DONE 상태 주문에서 결제 준비/승인 후 예상 환급, 청구 패키지 다운로드, 제출 링크를 확인합니다.

7. 알림 타입별 이동 경로 점검

현재 프론트의 NotificationBell 이동 규칙을 기준으로 빠르게 열어볼 수 있게 만들었습니다. 선택 주문 ID가 필요합니다.
